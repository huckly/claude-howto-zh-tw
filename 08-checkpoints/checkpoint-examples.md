# 檢查點範例

在 Claude Code 中有效使用檢查點的實際案例。

注意：檢查點會在每次使用者提示詞產生時自動建立。您無需手動儲存它們。要回溯，請按兩次 `Esc` (`Esc+Esc`) 或使用 `/rewind` 來開啟檢查點瀏覽器。

## 範例 1：資料庫遷移

### 情境
您需要從 MySQL 遷移到 PostgreSQL，但想探索直接遷移和逐步雙寫入方法。

### 工作流程

```
使用者：我們來實現從 MySQL 到 PostgreSQL 的直接遷移
      [自動建立檢查點 A]

Claude：我將實現直接遷移...
[變更資料庫驅動程式、更新查詢、修改 Schema]

使用者：執行測試
      [自動建立檢查點 B]

Claude：執行測試...
❌ 15 個測試失敗 - 連線池問題

使用者：這個方法有問題。我們來嘗試雙寫入模式。
[使用者按 Esc+Esc，選取檢查點 A，選擇「還原程式碼和對話」]

使用者：現在實現雙寫入模式，我們將同時寫入兩個資料庫

Claude：我將實現雙寫入遷移...
[實作雙寫入層，逐步遷移策略]

使用者：執行測試

Claude：執行測試...
✅ 所有測試通過

使用者：雙寫入方法顯然更安全。我們來提交這個。
```

## 範例 2：效能最佳化

### 情境
嘗試多種效能最佳化策略。

### 工作流程

```
使用者：我們來最佳化 API 回應時間。目前：450ms
      [自動建立 "Baseline" 檢查點]

Claude：我將新增資料庫查詢快取...
[實作 Redis 快取]

使用者：執行效能測試

Claude：結果：平均回應時間 280ms（38% 提升）

使用者：讓我嘗試不同的方法。
[使用者按 Esc+Esc，選取 "Baseline" 檢查點，選擇「還原程式碼和對話」]

使用者：嘗試資料庫查詢最佳化

Claude：我將最佳化資料庫查詢...
[新增索引，最佳化 N+1 查詢]

使用者：執行效能測試

Claude：結果：平均回應時間 180ms（60% 提升）

使用者：讓我也嘗試第三種方法。
[使用者按 Esc+Esc，選取 "Baseline" 檢查點，選擇「還原程式碼和對話」]

使用者：嘗試回應壓縮和 CDN

Claude：我將新增壓縮和 CDN...
[實作 gzip，設定 CDN]

使用者：執行效能測試

Claude：結果：平均回應時間 320ms（29% 提升）

使用者：查詢最佳化是最好的。讓我回溯並將其與快取結合。
[使用者按 Esc+Esc，選取查詢最佳化後的檢查點，選擇「還原程式碼和對話」]

使用者：現在在這些最佳化查詢之上新增 Redis 快取

Claude：[在這些最佳化查詢之上新增 Redis 快取]

使用者：執行效能測試

Claude：結果：平均回應時間 95ms（79% 提升）🎉

使用者：完美！這是贏家。我們來提交這個。
```

## 範例 4：除錯階段

### 情境
追蹤一個棘手的錯誤，並提出多種假設。

### 工作流程

```
使用者：應用程式中存在記憶體洩漏
      [自動建立「除錯前」檢查點]

Claude：讓我調查一下...
[分析程式碼]

使用者：我想是事件監聽器造成的。我們來修正那些。

Claude：[修正事件監聽器清理]

使用者：執行記憶體分析器

Claude：仍然洩漏記憶體 - 事件監聽器並不是問題

使用者：讓我回到之前，嘗試不同的假設。
[使用者按 Esc+Esc，選擇「除錯前」檢查點，選擇「還原程式碼和對話」]

使用者：或許是資料庫連線造成的？

Claude：[實施連線池修正]

使用者：執行記憶體分析器

Claude：仍然洩漏 - 並不是連線

使用者：讓我回到之前，嘗試另一種方法。
[使用者按 Esc+Esc，選擇「除錯前」檢查點，選擇「還原程式碼和對話」]

使用者：我們來檢查是否有循環參考

Claude：[找到並修正快取中的循環參考]

使用者：執行記憶體分析器

Claude：✅ 記憶體洩漏已修正！快取層中的循環參考是罪魁禍首。

使用者：太棒了！我們來提交這個修正。
```

## 範例 8：從檢查點摘要

### 情境
在長時間的除錯階段後，您想縮短對話，同時保留上下文。

### 工作流程

```
使用者：[經過 20+ 條訊息的除錯和探索]

[使用者按 Esc+Esc，選擇早期的檢查點，選擇「從這裡摘要」]
[可選地提供指示：「專注於我們嘗試過的事情以及哪些有效」]

Claude：[從該點開始產生對話摘要]
[原始訊息保存在記錄中]
[摘要取代可見的對話，減少上下文視窗使用量]

使用者：現在讓我們繼續使用有效的方法。
```

## 關鍵要點

1. **檢查點是自動的**：每次使用者提示都會建立一個檢查點——無需手動儲存
2. **使用 Esc+Esc 或 /rewind**：這是存取檢查點瀏覽器的兩種方法
3. **選擇正確的還原選項**：根據您的需求，還原程式碼、對話、都還原或摘要
4. **不要害怕實驗**：檢查點使您可以安全地嘗試激進的變更
5. **與 git 結合**：使用檢查點進行探索，使用 git 進行最終化的工作
6. **摘要長時間的階段**：使用「從這裡摘要」來保持對話可管理性
