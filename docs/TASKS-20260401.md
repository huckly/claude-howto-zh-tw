## Phase 1 — Infrastructure & Weak Modules (April 2026)

**目標里程碑：M1**

### Pillar 4: Newcomer Onboarding

- [ ] **T-001** — 編寫 `scripts/quickstart.sh`

  - 在 CLAUDE.md 末尾附加 agent-discovery 行，連結至 AGENT-INDEX.md
  - 冪等性：若檔案已存在則跳過並顯示警告，絕不覆蓋
  - 完成後印出後續步驟

- [ ] **T-002** — 建立 `QUICKSTART.md`（前 15 分鐘視覺指南）
  - 將終端機步驟以程式碼區塊形式標註（盡量避免使用 PNG 截圖；優先使用 ASCII 或 Mermaid）
  - 記錄哪些指令會產生各項視覺內容，以便重新擷取

- [ ] **T-003** — 為所有 10 個模組的 README 加上難度標籤
  - 格式：`> 🟢 **Beginner** | ⏱ 30 minutes` 位於每個模組 README 的頂部
  - 在標籤下方加入「你將建立什麼」的項目預覽

### Pillar 7: Living Curriculum

- [ ] **T-004** — 建立 `WHATS-NEW.md`
  - 格式：`## CC vX.X — DATE` 並列出每個功能變動的項目
  - 至少為目前的 CC 版本新增一筆紀錄

- [ ] **T-005** — 為所有 10 個模組的 README 加上版本標籤
  - 格式：`> ✅ Verified against Claude Code **vX.X.X** · Last verified: YYYY-MM-DD`
  - 在每個模組的 frontmatter 中加入 `cc_version_verified`

- [ ] **T-006** — 建立 `.github/workflows/staleness-check.yml`
  - 排程：每週一 09:00 UTC
  - 從 frontmatter 讀取每個模組的 `last_verified` 日期（使用 `yq` 或 10 行 Python 腳本）
  - 若有任何模組超過 30 天未驗證，則建立一個 GitHub Issue
  - 若已存在相同標題的開啟中 Issue，則跳過

### Pillar 6: Content Quality (CLAUDE.md)

- [ ] **T-007** — 為專案建立根目錄 `CLAUDE.md`
  - 將最佳實踐作為專案本身的配置進行展示
  - 記錄貢獻規範、模組結構與維護工作流程

### Pillar 2: AI Agent Index (Generator)

- [ ] **T-008** — 編寫 `scripts/build-agent-index.py`
  - 讀取所有 10 個模組的 README 檔案
  - 提取：標題（→ 主題）、程式碼區塊（→ 帶有語言標籤的範例）、表格（→ 參考數據）
  - 輸出符合 CEO 計畫中定義之 schema 的 `agent-manifest.json`
  - 輸出 `AGENT-INDEX.md`（人類可讀的摘要）
  - 驗證引用是否指向實際檔案

### Module 08-checkpoints: 全面深度審查 (311 → 800+ 行)

- [ ] **T-009** — 使用真實場景重寫模組介紹

- [ ] **T-010** — 加入檢查點策略決策樹 (Mermaid 流程圖)

- [ ] **T-011** — 加入 3 個工作流程範本

  - 災難復原工作流程

- [ ] **T-012** — 加入與規劃模式整合的章節

- [ ] **T-013** — 加入檢查點生命週期的 Mermaid 圖表

- [ ] **T-014** — 加入 2 個以上帶有可驗證指令的「立即嘗試」區塊

- [ ] **T-015** — 加入「模式與食譜」章節，包含 2 個以上具名的模式

### Module 06-hooks: 全面深度審查
